# RC8 device-token readiness report

Audited and tested locally: 2026-08-31

## Final state

**BLOCKED — FIX REQUIRED**

The hosted RC7 foundation securely verifies HMAC-peppered device credentials, enforces device/user binding, fixed `health:ingest` scope, expiry, revocation, and safe logging. However, the deployed Production source has no owner-facing issuer: its trusted service RPC accepts a plaintext token generated by some other privileged caller. Production therefore cannot yet satisfy the requested server-generated, one-time-display owner flow.

A complete fix is prepared and green on the local `codex/rc8-unattended-prep` branch. It was deliberately not applied to hosted Supabase or Vercel while unattended because adding a credential-issuance security boundary is not a trivial read-only hosted change.

## Prepared implementation

Migration `20260831084851_rc8_owner_ingestion_credentials.sql` adds four narrowly granted owner RPCs:

- `create_ingestion_credential(text)` creates an owner-bound Apple Shortcut device and credential in one transaction.
- `rotate_ingestion_credential(uuid)` revokes prior credentials before returning a replacement once.
- `revoke_ingestion_device(uuid)` revokes the owned device and every active credential.
- `list_ingestion_devices()` returns only device metadata and a six-character token hint; it cannot return plaintext or a stored digest.

Security properties:

- 32 cryptographically random bytes are generated inside Postgres and encoded as 64 lowercase hexadecimal characters.
- The authenticated user is derived only from `auth.uid()`; no caller-supplied owner ID is accepted.
- The database creates the device UUID and uses the same identifier in the Shortcut header and JSON envelope.
- Scope is fixed to `health:ingest`.
- Pilot credentials expire after seven days.
- Only an HMAC-SHA-256 digest using the existing Vault-held project pepper is stored.
- The retained hint contains only the final six random characters.
- Plaintext exists only in the one RPC response and is not available from later list calls.
- Create, rotate, revoke, and list functions are denied to `anon`, use an empty `search_path`, and contain no dynamic SQL.
- A maximum of three active Apple Shortcut devices per owner limits accidental credential proliferation.
- Per-owner and per-device row locks serialize creation, rotation, and revocation, while a partial unique index enforces one unrevoked credential per device.
- The existing service-only issuer now derives its own safe hint, validates the token shape, revokes the prior credential transactionally, and follows the same one-active-credential invariant.
- Control characters are rejected from device names in both the Server Action and the database.
- Vercel needs no service-role key, database password, or ingestion pepper.

The owner UI is prepared at `/settings/ingestion`. It rechecks authentication inside every Server Action and relies on the database for an independent ownership check. A credential is displayed in response state only, never in a URL, cookie, redirect, log, report, or repository file. Refreshing the page cannot retrieve it again. The UI also exposes rotate and revoke controls without exposing token hashes.

## Hosted boundary

No owner Production credential was created. No plaintext token was printed or recorded. No Production data or schema was changed. To clear this block, the migration and matching application UI must receive normal review, exact-head CI, merge, migration application, and Production deployment before the owner creates a real device credential.
